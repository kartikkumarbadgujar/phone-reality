# BudgetBench

**Test beyond the flagship. Build for every phone.**

BudgetBench is a small reliability lab for the failures that are easy to miss on a fast phone and a steady connection. It keeps the useful parts of the PhoneReality HTTP tester and adds projects, an Android device snapshot page, saved run history and a place to review findings.

The main demo is an upload that times out. The server may have saved the file before the client gave up waiting. Retry without protection and the server can save it twice. Turn on de-duplication and run the same test again to see the difference.

## Run it on your computer

You need Python 3.11 or newer. Android Platform Tools are only needed for the Device Lab.

In PowerShell, create and activate an environment, then install the packages:

```powershell
py -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Start the demo service in one terminal:

```powershell
python demo_app.py
```

In another terminal, from the project folder, start BudgetBench:

```powershell
streamlit run app.py --server.address localhost
```

Open `http://localhost:8501`. The test lab sends real HTTP requests to the local demo service. For Android snapshots, enable USB debugging, connect your phone, approve the computer on the phone, then check the connection with `adb devices`.

## A good first run

1. Create a project, or go straight to **Run Tests**.
2. Pick **Upload** and the **Slow Network** profile.
3. Run once and compare the client timeout with the server receipt.
4. Add a retry and run again. Without de-duplication, the server can keep two copies.
5. Turn on server de-duplication, repeat the test and check that only one copy remains.
6. Open the finding to review its evidence, then reproduce it or download a report.

The delay and HTTP 503 scenarios are controlled faults in the demo service. Packet loss is generated by a repeatable simulation. BudgetBench labels these results so they are not mistaken for measurements of a real mobile network.

## Where the data goes

- Test records remain in `data/results.json` for compatibility with PhoneReality.
- Projects and Android snapshots are stored in `data/budgetbench.sqlite3`.
- Set `PHONEREALITY_DATA_DIR` to move the JSON data, or `BUDGETBENCH_DB` to move the SQLite database.
- The device serial is used locally to associate snapshots. It is not included in the legacy reports.
- The demo server is for local evaluation. It only accepts loopback requests, caps request size at 6 MiB and keeps no more than 1,000 uploads or 256 MiB of upload data.

The hosted demo has no login and shares its workspace between visitors. Its local files can be cleared when the service restarts. Treat it as a guided demo, not a private team workspace, and do not put sensitive data in it.

## What this build can and cannot show

BudgetBench can run real HTTP requests against its demo service, inspect server-side upload receipts, apply eight rule-based detectors, replay saved settings and export JSON, CSV or Markdown. With an authorized Android phone, Device Lab can collect a read-only snapshot of available system details.

The HTTP demo does not measure Indian mobile networks or throttle a phone. ADB readings are system-level; they are not app-specific memory measurements. Continuous monitoring, network shaping, native app journeys, Playwright tests, Neo4j writes, individual accounts and PDF report generation are not part of this build. The interface calls out these limits where they matter.

## Tests

Run the automated suite with:

```powershell
python -m pytest -q
```

The final build audit dated 21 November 2026 recorded **74 passing tests** across the HTTP demo, findings, scoring, storage, reproduction, Android parsing and Streamlit pages. That audit did not include a physical-device test or browser end-to-end tests in CI.

## Project map

- `app.py` draws the Streamlit pages and handles navigation.
- `tester.py` runs requests and records what happened.
- `demo_app.py` is the local service used by the test lab.
- `detectors.py` checks each run against explicit rules.
- `scoring.py` calculates priority from severity and team-set weights.
- `storage.py` and `database/db_manager.py` save results and workspace data.
- `core/adb_controller.py` runs bounded, read-only ADB commands.
- `report_generator.py` creates JSON, CSV and Markdown exports.
- `assets/style.css` contains the BudgetBench visual styles.
